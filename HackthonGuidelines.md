📌 Submission Requirements
● Your project must be:
○ ✅ Open Source (GitHub Repository)
○ ✅ Deployed on Vercel
○ ✅ Include a proper README.md with complete documentation

📖README.md

🔒 Important Rules
● ⛔ Strict time limit: 11:00 AM to 11:00 PM IST
● ⛔ No commits/changes allowed after time is up
● ❗ Any updates after the deadline → Immediate Disqualification
● ✅Ensure your project is working before submission.

Disqualification Rules
A submission may be disqualified if:
❌ Commits or code changes are made after the submission deadline.
❌ The GitHub repository or deployed application is inaccessible.
❌ The project is submitted without a README.md.
❌ The submission is incomplete or missing required links.
❌ The participant submits someone else's work or violates the hackathon rules.

Frequently Asked Questions (FAQs)
Q1. Can I use AI tools like ChatGPT, Claude, Gemini, or Cursor?
Yes. This is an AI-focused hackathon, and you are encouraged to leverage AI tools to
accelerate your development and problem-solving. However, you should understand the code
and solution you submit.

Q2. Can I use open-source libraries or frameworks?
Yes. You may use publicly available open-source libraries, frameworks, and SDKs. Ensure you
comply with their respective licenses where applicable.

Q3. Can I start with an existing boilerplate or template?
Yes. You may use a basic project scaffold or boilerplate (e.g., Next.js, React, LangChain
starter). However, the core functionality developed for the hackathon should be your own work
completed during the event.

Q4. Can I modify my GitHub repository after the submission deadline?
No. Any commits, pushes, or code changes made after the official deadline will lead to
disqualification.

Q5. What if my Vercel deployment fails just before submission?
Please try to resolve the issue before the submission deadline. Only projects submitted before
the deadline with the required repository and deployment links will be considered for evaluation.

Q6. Can I update my README.md after submission?
No. The repository, including the README.md, must remain unchanged after the submission
deadline.

Q7. What will the judges evaluate?
Projects will be evaluated based on:
● Idea & Innovation
● AI Implementation
● Functionality
● Code Quality
● Documentation (README)
● UI/UX

Q8. How many times can I submit?
Only one final submission will be evaluated. Please verify all links before submitting the
Google Form.

Q9. What happens if my GitHub or Vercel links are inaccessible?
Participants are responsible for ensuring that all submitted links are valid and accessible.
Inaccessible repositories or deployments may negatively impact evaluation or result in
disqualification if the project cannot be reviewed.

Q10. Who should I contact if I have questions during the hackathon?
Please use the official communication channel announced by the organizers. Only queries
related to rules or logistics will be addressed during the hackathon.

We wish all participants the very best. Build something innovative, solve a real QA
challenge, and enjoy the experience! 🚀
